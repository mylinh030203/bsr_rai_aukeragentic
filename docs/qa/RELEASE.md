## Release smoke cases (all PASS on the hosted build)

Health endpoint; SPA shell served; leadership sees 3 of 3 reports and reads the
confidential one; internal lists only 2 and receives `404 not_found` (not `403`)
for the confidential report; leadership without `can_export` receives
`403 export_denied`; MI export returns `200 application/pdf` starting with
`%PDF-1.4`; non-admin permission change → `403 forbidden`; admin permission
change → `200`; audit log contains `sign_in/succeeded`,
`export_attempt/denied`, `export_attempt/allowed`, `permission_change/succeeded`;
state change without the CSRF header → `403 csrf_failed`; online backup is
integrity-checked.

Earlier smoke runs surfaced two evidence defects that were fixed rather than
worked around: the script asserted an `export_denied` *action* while the app
records `action=export_attempt, result=denied` (confirmed against the hosted

## Production-mode behavior (observed)

With `BSR_ENV=production` the demo role sign-in returns `401` because seeding is
off in production: there is no synthetic user to sign in as, which is the
intended separation between the demo workspace and a real deployment. The
session cookie is forced `Secure` in production (`app/api/auth_routes.py`:
`secure = request.is_secure or SESSION_COOKIE_SECURE`), so production must sit
behind HTTPS; the cookie flag path was reviewed in source and is covered for the
HTTPS case by `tests/test_auth.py::test_secure_cookie_on_https`.

## Hosted this session

Native release host on `http://127.0.0.1:8000` (waitress, development
environment, fresh seeded database under `tmp/`), used for the smoke run and

```bash
# native, no Docker needed
BSR_ENV=development BSR_SEED_ON_START=1 python run_prod.py      # http://localhost:8000

# Docker, once the engine is available (demo overlay)
docker compose -f docker-compose.yml -f compose.demo.yml up -d --build
```

Demo accounts are the published role buttons (leadership, MI, internal); there
are no passwords.
